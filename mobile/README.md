# RHM Flutter Android client

This folder contains the Flutter client, its Dart tests, Android build templates and the API client for the existing RHM FastAPI service.

- Current package version: `0.1.10+11`.
- Minimum SDK constraints: Dart 3.13+, Flutter 3.47+.
- The Android Gradle project is generated by `../scripts/prepare_android_project.sh`; the script preserves Flutter's generated Gradle DSL and applies minSdk/desugaring changes without replacing it with the legacy Gradle template. Generated build output is ignored.
- The client stores its server URL and device-specific access/refresh credentials locally using Android-backed secure storage. The legacy master-token connection remains available for compatibility; the new pairing flow does not copy the master token into the Flutter client.
- First-time device pairing uses a 10-minute one-time code, explicit approval from the Termux CLI, and an Ed25519 proof of possession. Access credentials rotate automatically; see [device pairing](../docs/DEVICE_PAIRING.md).
- Android voice recognition and text-to-speech depend on services and language packs installed on the device.

Read the repository-level README and `docs/` before changing API routes, update behavior, signing, or runtime architecture.


- Android application ID generated by the current preparation script: `com.rhm.rhm_mobile`, matching the org/project-name values in the private RHM Android CI workflow. Verify against the installed APK before release; do not infer signer compatibility from the application ID alone.


## Android host status

The generated Android host includes Kotlin foreground monitoring, a notification channel, a Flutter method channel, and a boot receiver whose preference is off until the user enables it. The service checks the local `GET /health` liveness endpoint at `127.0.0.1:8000`; this does not share the app's rotating credentials and does not prove database or model-provider readiness. Authenticated app readiness is checked separately by Flutter through `GET /mobile/health`.

Debug builds receive the application ID suffix `.debug` to keep them separate from the release app. The intended release ID remains `com.rhm.rhm_mobile`; verify the installed APK identity and signer before any release.
